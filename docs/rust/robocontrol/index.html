RoboControl — controle e gravação do braço 4-DOF por USB.

O firmware continua dono do movimento (rampa, limites, hold). Aqui só propomos alvos a 20 Hz e mostramos o que a placa responde.

§Arquitetura

Este crate é só a interface (egui/eframe). Cada responsabilidade tem um módulo e um dono único:

MóduloResponsabilidade
protocolgramática serial, unidades e parsing
linkporta serial + thread de leitura
motiongravação, interpolação e arquivos JSON
iconsdesenho vetorial dos ícones e botões

§Máquina de estados

desconectado → joystick → PC e volta. O campo App::pc é só um espelho do pc_mode que o firmware manda no status: o firmware é a fonte da verdade. Se o joystick físico assumir, o app larga o replay e os alvos sozinho.

§Invariantes de segurança

  • STOP (#H) está sempre visível e devolve o controle ao joystick.
  • Tocar num pad cancela replay e alvo manual: quem está com a mão manda.
  • A trava da garra é um único estado no firmware (botão D4 e app), e com ela ativa a garra só aperta.
  • Os limites usados na validação da UI vêm do diagnóstico; quem os aplica de verdade é o firmware, então um alvo fora da faixa não vira movimento.

§Ritmo

TICK = 50 ms: a cada tick drenamos a serial, gravamos uma amostra e, se o PC está no controle, enviamos novos alvos/sticks. O diagnóstico é pedido a cada 2 s e a UI repinta a cada 20 ms.

§Layout

Responsivo por largura/altura disponível: dock lateral a partir de 1024 pt, topbar em uma linha a partir de 1024, pads lado a lado a partir de 760, variante compacta quando a altura fica abaixo de 380. A janela mínima é 760×320, que ainda comporta os pads empilhados.

Movimentos gravados ficam no diretório de dados do usuário, nunca no cwd — ver dir_movimentos.
