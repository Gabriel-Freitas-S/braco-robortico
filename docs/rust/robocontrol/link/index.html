Porta serial em thread de leitura + escrita síncrona.

Escrever direto da thread da UI é barato: um comando tem ~10 bytes, 1 ms a 115200. Quem precisa de thread é a leitura, que fica bloqueada esperando.

§Modelo de execução

  • Link::open abre a porta, clona o handle e sobe uma thread leitora.
  • A thread acumula bytes até \n, interpreta com protocol::parse_line e entrega Events por um canal mpsc.
  • A UI chama Link::drain a cada tick (20 Hz), sem bloquear; a thread nunca toca em estado da UI.
  • Link::send é best-effort: erro de escrita é descartado. Se o cabo cair, a thread leitora envia Event::Error e o app desconecta.

O timeout de leitura (200 ms) não é timeout de protocolo: existe só para a thread conseguir sair quando o canal fecha.
